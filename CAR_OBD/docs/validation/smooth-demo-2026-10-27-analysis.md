# Calm demo and smooth numerals, 2026-10-27

Firmware 0.3.3 combines the requested slow demo and replacement of seven-segment
speed digits with smooth Roboto Condensed Bold numerals.

## Behavior

Demo repeats 11, 22, 33, 44, 55, 66, 77, 88, 99, 111, holding each for three
seconds. The first gauge frame uses 11; returning from LIVE to DEMO restarts
the sequence at 11. Real OBD speed retains the existing polling/update behavior.
Low-rate `DEMO_STEP` records capture the demo transitions for verification.

The speed font uses weight 700, rasterized at four times resolution, downsampled
to 58x120 cells and quantized to four-bit alpha. Ten glyph masks occupy 34,800
bytes in flash. The renderer uses a 16-color RGB565 blend palette on the stack;
there is no runtime font engine or additional framebuffer. All ink right edges
are aligned. Leading-bearing metadata centers visible numerals while retaining
fixed cell positions throughout 100..199. Small unit/detail text is unchanged.

The source TTF, original metadata and OFL license are retained under
`assets/fonts/roboto-condensed`. The checked-in `src/display/SpeedFont.h` is
generated by `tools/generate_speed_font.py`; regular builds need no font download
or Pillow installation. Font source SHA256 is recorded alongside the asset.

## Verification

- Existing ASAN/UBSAN suites passed for redraw equivalence/guards, themes/pages,
  button gestures, OBD parsing/scheduling and flash-journal behavior.
- Updated the existing obsolete sine-demo expectations to verify each requested
  step's first/last millisecond, the 30-second wrap and long uptime arithmetic.
- Native-renderer previews were visually checked at 11, 99, 100, 110, 199 and 255
  in day/night themes. Preview readings/status colors are synthetic examples.
- Examined all glyph pixels for every speed 0..255: every nonzero alpha pixel
  stays inside the arc's inner radius. Largest squared radius was 10,088,
  below the arc boundary of 10,609.
- Native ESP-IDF build/upload succeeded; flash data hash was verified.
- A 40-second serial capture confirmed boot 0.3.3 and the complete sequence
  `[11,22,33,44,55,66,77,88,99,111,11,22]` including wraparound.
- Observed adjacent USB delivery intervals were 2.960..3.043 seconds, consistent
  with three-second steps plus frame scheduling/log delivery latency.
- Runtime health showed 46,952 bytes free heap and 728 bytes main-stack
  high-water space, with no firmware crash. Recorded drawing maxima were
  approximately 57, 60 and 92 ms. Startup brightness remained 100%.
